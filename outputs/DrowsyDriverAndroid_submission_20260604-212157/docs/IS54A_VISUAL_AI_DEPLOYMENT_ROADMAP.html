Roadmap Trực Quan IS54A

Hệ thống phát hiện và cảnh báo buồn ngủ tài xế: xây mô hình AI, deploy Android native, chuẩn bị Streamlit fallback và đối chiếu toàn bộ tiêu chí chấm điểm.

Pipeline bản chính nên bảo vệ

CameraXĐiện thoại Android lấy frame realtime.
MediaPipeTìm mặt, mắt, miệng bằng Face Landmarker.
EAR/MAR + CNNLuật nền ổn định, CNN phân loại mắt mở/nhắm.
TFLite + AlertChạy on-device, cảnh báo rung/âm thanh.

Chiến lược nộp chắc

Android native là sản phẩm chính. Streamlit là bản demo phụ để trình bày thuật toán, dataset và kết quả.

YOLO/FastAPI/embedded nên đưa vào hướng phát triển, trừ khi đã có đủ dataset bounding box và thời gian tích hợp.

Lộ Trình Làm Từ Dataset Đến Demo

Bước 1

Chuẩn bị dữ liệu

  • Tải MRL eye-state dataset.
  • Chuẩn hóa train/val/test.
  • Thống kê số ảnh từng lớp.
Bước 2

Train CNN

  • Input ảnh mắt 64x64x3.
  • Output eyes_open, eyes_closed.
  • Export drowsiness_model.tflite.
Bước 3

Evaluate

  • Accuracy, precision, recall, F1.
  • Confusion matrix.
  • Nhấn mạnh recall lớp nhắm mắt.
Bước 4

Deploy Android

  • Đặt model vào assets.
  • Run bằng Android Studio.
  • Quay demo nhắm mắt/ngáp.
Bước 5

Báo cáo và backup

  • Điền số liệu thật vào Word.
  • Chạy Streamlit fallback.
  • Đóng gói zip nộp.

Deploy: Nên Nói Thế Nào Cho Gọn

Hướng deployVai tròNên dùng trong bàiRủi ro
Android native Bản chính chạy on-device. Có, ưu tiên cao nhất. Cần Android Studio, điện thoại, quyền camera.
Streamlit Fallback web demo/dataset dashboard. Có, làm bản phụ. Không phù hợp cảnh báo realtime thực tế bằng Android.
FastAPI/Flask Server inference nhận ảnh/frame. Ghi hướng mở rộng. Phụ thuộc mạng, độ trễ, bảo mật dữ liệu khuôn mặt.
Raspberry Pi/Jetson Embedded với camera riêng. Ghi hướng phát triển. Cần phần cứng, tối ưu tốc độ và cảnh báo ngoài.
YOLO end-to-end Detect trực tiếp mắt mở/nhắm/ngáp. So sánh hoặc mở rộng. Cần bounding box labels, export và post-processing khó hơn.
